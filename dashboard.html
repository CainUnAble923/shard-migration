Settled

Stay on ModernUO. Port ServUO content in, indefinitely.

ModernUO stays modern (.NET 10, source-generated serialization, fast saves, real tests). ServUO is a read-only content source. Scope is all the newer content, worked as an ongoing backlog with no completion date. The percentage above exists because S3 and S9 built a denominator by filtering ServUO against what ModernUO already ships; it is a direction of travel rather than a deadline.

No migration. No cutover, no fresh world, no account export, no password window. Our existing custom scripts are never rewritten, and every port leaves a working shard.

Governing principle

Port unchanged, so the existing wikis do our documentation

Content matching OSI behaviour is content nobody has to document. Players use UOGuide and Stratics instead of a custom wiki. Every deviation is a page only we can write, so keep ServUO's defaults, and prefer turning a system off over running it differently.

Correction log

Findings that changed a decision

  • Eodon separates. 60% of Eodon-family content (89 files, 25,354 lines) touches no missing subsystem. The earlier "83% dependent" measured the Myrmidex folder, not Eodon, and made the Valley look gated when it is not.
  • Custom facets are available. The six-facet ceiling is an official-client limit, not a ClassicUO one. Immortal Realms runs map0 through map21 in production.
  • The canonical tree was never complete. The old build sourced server/uo/, so a green build never proved server/customizations could stand alone. It could not.
  • Both drafted fidelity traps were wrong, one exactly backwards. ServUO's own constructor rewrites range perception 10 to 16, so it already runs at ModernUO's default; the recipe's "correct" example would have narrowed perception across nearly the whole creature roster. And ServUO ignores its own two speed arguments entirely — speed is derived from Dex. The recipe is now written from a build and a running client, not from reading source.
  • The Eodon file count was wrong twice. A keyword search on Tribe caught 43 generic Britannia mobs. Real core Eodon is ~22 files, ~4,000 lines, not 52. Standing rule since: a keyword hit is a candidate, not a result, and the file list gets published beside the count.
  • The progress tooling could not see ported content. It counted server/customizations with a top-level glob, but F2 put ported content in subdirectories — so every future port would have been invisible to the counter and to expansion coverage. Fixed 2026-09-06.
  • "Creatures and NPCs, 0% dependency" was false. Measured across all 462 ServUO Mobiles/Normal files: only 275 (60%) are clean. 132 call Pet Training methods ModernUO's BaseCreature does not have, and 89 reference a type ModernUO lacks. 40% of the directory needs a decision before it needs effort, so batches are drawn from the clean 60% only.
  • Build cycles are not the dominant porting cost. Measured on the second port: per-file work about 1:10, a warm build cycle 0:44. Batching builds saves roughly ten minutes in sixty, which is the opposite of what "build after every file" assumes. A batch of 20 is about an hour.
  • There is no readable ModernUO source on the machine. We port to ModernUO and cannot grep it, so every "does this type exist" question costs a build cycle. server/uo/ is not a checkout; it is one directory, 161 files, against ModernUO's 7,058 types. Fix is a pinned read-only clone beside the ServUO reference.

Where these numbers come from

Counts come from the working trees on every run of tools/progress.py. Judgment items live in tools/progress-state.json. Dependency percentages are the share of files in an area referencing a subsystem ModernUO ships zero files for. Source for this page: dashboard.html in the migration repo.
