## The risk nobody had looked at: ServUO name collisions

Five customization files share a filename with an existing **ServUO** script. Dropping them
into `Scripts/Custom/` produces duplicate type definitions and the build fails, or worse,
resolves to the wrong one.

| Our file | Collides with ServUO |
|---|---|
| `CharacterCreation.cs` | `Scripts/Misc/CharacterCreation.cs` |
| `CraftItem.cs` | `Scripts/Services/Craft/Core/CraftItem.cs` |
| `HammerOfHephaestus.cs` | `Scripts/Items/Tools/HammerOfHephaestus.cs` |
| `Meditation.cs` | `Scripts/Skills/Meditation.cs` |
| `RegenRates.cs` | `Scripts/Misc/RegenRates.cs` |

These are the same five that replace upstream files in ModernUO, which makes sense: they
were always stock replacements rather than additions.

**Consequence for the ServUO layout:** these five do not belong in `customizations` at all.
They become **patches** against the stock ServUO file, and `apply-patches.sh` routes them to
their ServUO source paths. Note `HammerOfHephaestus` already exists in ServUO as a real
item, so the first question is whether our version is still needed or whether ServUO's
covers it.

## Recommended port order

1. **One trivial file end to end** to prove the pipeline. Codex already did
   `CleanedDebris.cs`. Done.
2. **The bulk-repetitive trio** (`ClusterFGargoyleVendors`, `ClusterFExtendedOres`,
   `ClusterFExtendedLumber`). 68 types for one pattern. Claude drafts, Codex builds.
3. **The 82 trivial files**, drafted in batches by Claude.
4. **The 25 mechanical files**, which need per-file attention to serialization and gumps.
5. **The five collisions, last and as patches.** Assess each first: ServUO may already
   provide the behavior, in which case the patch is dropped rather than ported.

Baseline recovery still blocks all of this. Nothing in steps 2 through 5 can be verified
until the canonical tree compiles.
