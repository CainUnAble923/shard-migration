# P527: companions and evo pets, design against main

Reviewed October 24, 2026. Notes only. Recommendations below are proposals for the overseer and Chase, not new decisions or implementation authorization.

Main contains the companion foundation, a working evo stage framework, and P365's reward mounts and extra evo lines. It does not yet provide the designed adventuring party: players cannot hire a human companion, earn its promotions, or use the proposed class roles, rooms, or courier. Evo pets can be obtained through the tutorial, but normal progression stops at owner-loop gates that are not connected to the tutorial's existing loop counter. The Bond Trial and role abilities are also unfinished.

## Design questions and recommended answers

These are non-blocking recommendations for future prompts. They do not change defaults or settle Chase's open decisions.

| Question | Recommended answer and reason |
|---|---|
| How do six ranks fit the revised 21-loop ladder? | Keep six named rank milestones at max levels 50, 100, 125, 150, 175, 200, corresponding to loops 0, 1, 6, 11, 16, 21. Derive rank from the approved table during earned promotion. This preserves the original power bands and top rank at 200. Moving branch choice from literal loop 3 to rank 3/loop 11 is a proposed design change that needs an explicit answer. Do not silently keep rank and loop independently player-editable. |
| What grows party size, and what is the slot budget? | Use the same permanent max-level milestones, never current level. Preserve five companion seats at the top, rank costs 1/1/2/2/3/3, a floor of five follower slots, and the shared pet budget. Remap the old party table to the new milestones rather than automatically giving the full party at raw loop 5. Five top-rank companions cost 15; an ordinary one-slot mule and the accepted one-slot evo pet make 17. The present top follower setting is 19, so that example fits. Recheck the separate case where every companion has a real mount before finalizing its exemption. |
| Can the owner-loop hooks wait until full F-12 exists? | Connect both to the existing ClusterFLoops.LoopOf now in a small follow-up with regression coverage. Record graduation's loop 1 honestly. Do not fabricate higher loops or mark Bond Trials complete. Later F-12 must notify progression and follower caps when the real loop changes. |
| Which reset policy should companions follow? | The old unconditional skill wipe conflicts with current F-12 Keeper/Breaker rules. Reuse the approved F-12 progression math and offer the same permanent Keeper/Breaker choice on the companion's first earned loop, saved on that companion. Chase must accept that extension before building it. Keep stats, rank milestones, identity, and owner-independent progress through the owner's reset; never downscale an established companion beside a reset owner. |
| Which personality system governs? | The companion design's nine: Noble, Commoner, Devout, Sellsword, Scholar, Braggart, Ditzy, Gloomy, Isekai'd. Roll 5% Gloomy and 1% Isekai'd, splitting the other 94% only among commons allowed by the purchased path. Author accessory foot moments for those voices and retire or bridge the unrelated six-value accessory API without rerolling saved companions. Do not invent a nine-to-six personality conversion. |
| How much speech is required for the first useful release? | Ship the documented personality lines plus all branch combo epithets/signatures, gendered rank titles, and required state-change moments. The combo file contains 50 rows: Noble, Commoner, Devout, Sellsword, Scholar, Braggart, Ditzy each have four; Gloomy and Isekai'd each have eleven. Those sections list every pairing. Path-only combo lines before branch choice and party banter can wait. Keep Epithet/Title separate from Name; make idle chatter sparse and suppressible. |
| Should personalities and class tables be live editable? | Yes, use corrected B2's validated JSON tables and last-good reload. Keep enum identities stable and validate cross-table path/branch restrictions. Retain server settings for scalar tuning. A bad reload must not strand existing companions or their rooms. Evo stage rows can stay in their existing compiled table; that was a separate deliberate implementation choice. |
| What is the minimum player hiring release? | Build both intended sources: path contracts and a candidate board hiding personality until hire. Set a clear data-driven Renown price and a higher candidate premium; do not adopt the source Squire's 100k gold price by accident. Require shared slot/count checks, permanent-choice confirmation, bonded ownership history, a usable equipment/lore flow, and safe lifecycle behavior before release. |
| Is near-player skill math sufficient? | Preserve the decided parity work: remove pet-only gain boosts for companions, use player stat timing, enable their Bushido, and implement the Healing resurrection exception. Audit creature-only skill branches instead of treating the narrow B1 parity test as exhaustive. Keep free casting as the already accepted temporary exception. Ordinary evo pets retain ordinary pet math. |
| How should companion mounts be owned and counted? | Prefer player-controlled mounts assigned to one companion, with saved assignment and an audited slot exemption while assigned and ridden or stored. This works with the existing PlayerMobile-based shrink path and avoids creatures owning creatures. Require dismount/storage before rooming, and normal slot checks when returning a mount to the player's free pet pool. Ethereal mounts also need explicit accounting and NPC region guards; direct Rider assignment alone does not implement the desired exemption. |
| What rooms and courier policy is safest? | Separate persistent inn rooms from Animal Trainer stables. Restore safety flags before abandonment sweeps. Rent can block new service or accrue debt, but should not delete a companion. Courier travel is delayed and checks ownership, combat, travel restrictions, capacity, and cooldown again at delivery; a pigeon never becomes an ownership token. |
| How should Drill Orders and class skill access work? | Restrict gains to approved class skills after the general Squire stage; allow up/down/locked settings within that list. Drill Orders speed use-based gain below min(previous peak, current cap), never grant skill points. Use five path trainers and confirmation for an irreversible valid branch. Auto-loot should default off and allow at most one nominated looter. |
| Should rare branches be cut because the engine cannot support them? | No. P45 establishes viable seams. Keep Penitent available off any Gloomy path and Otherworlder off any Isekai'd path, retaining base-role AI. Use a persisted per-owner shared cheat-death cooldown. Include player Shared Burden only with the explicitly scoped damage hook and recursion checks; settle its percentage and cooldown through a separate balance proposal. |
| What is the first Bond Trial? | A repeatable party-safe encounter where the owner and that pet both participate, with completion saved on the pet. Death/disconnect should permit retry without consuming the pet or its XP. Keep the final-stage gate until it is earned. Design and implement the trial rather than adding a player button that sets the staff flag. |
| Where should Horse and Lizard come from, and are they mounts? | Offer them later through the League or an earned pet reward, leaving the farm Dog/Cat lesson and existing starter list unchanged unless Chase expands it. They remain evo combat pets using one slot. A rideable evolving horse is separate design work involving mount serialization and stage-specific mount art; do not re-parent already saved EvoPets to BaseMount. |
