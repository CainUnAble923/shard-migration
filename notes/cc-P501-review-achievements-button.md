## Findings

1. **bug** - `client/patches/0003-shard-buttons-achievements.patch:300` (`ShardButtons.MarkOffered`): `_hooked` allows a disconnect handler on only the first socket, but login replaces the socket, so after two logins to our shard followed by a login to a shard that sends no enhanced handshake, Achievements stays visible and its clicks send a request that opens nothing. Track the subscribed socket, detach and attach when it changes, and test that disconnecting the second socket clears availability before connecting to a server that never offers id 4.

2. **bug** - `client/patches/0003-shard-buttons-achievements.patch:232` (`EnhancedClientCommand.SendAck`): the enabled-packet set retains id 4 from an earlier connection, so a later server's handshake listing only other IDs still calls `MarkOffered` and displays Achievements even though that server never offered it. Clear the enabled-packet set at each connection boundary and determine availability from the current server's offer; add a regression that negotiates id 4, reconnects, and receives a handshake without it.

3. **risk** - `client/patches/0003-shard-buttons-achievements.patch:389` (`ShardButtonsTests`): the availability test calls `MarkOffered(null)` and `Reset` directly, and no test in that class creates or clicks the classic paperdoll, modern menu, or top bar, leaving both connection bugs and the missing-art fallback outside its coverage. Add UI coverage for all three click paths, another character's paperdoll, delayed negotiation, and a client missing gumps 22456 through 22458, checking that Help remains usable and the menu and top bar can still request achievements.
