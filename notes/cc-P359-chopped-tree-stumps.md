## Source findings and patch choice (before implementation)

- Pinned `Projects/UOContent/Engines/Harvest/Lumberjacking.cs`: 4 by 3 banks, 20–45 logs, 10 per swing (20 in Felucca), 20–30 minute refill. `ClusterFLumberjackingExtension.ApplyExtendedVeins` keeps veins permanent, not randomized.
- Pinned `Engines/Harvest/Core/HarvestBank.cs`: the first consumption schedules the refill, including the elf discount. Later chops do not extend it. `Current`, `Vein`, and `Consume` call `CheckRespawn`; banks are only in memory. A balance of 1–9 is already unharvestable, so it must show the exhausted marker too; otherwise most random bank totals would never produce a stump.
- Pinned `HarvestSystem.FinishHarvesting` consumes before `OnHarvestFinished`, which receives the original target and bank. Use that existing virtual in our Lumberjacking partial, validating the targeted static and its bank (never the player's bank). No depletion patch is needed.
- A small HarvestBank patch is needed to expose the actual `NextRespawn` deadline and notify our marker registry immediately on refill. Alternatives: polling can lag and scans idle banks; guessing 20–30 minutes loses the first-chop deadline and elf modifier; reflection couples production to private fields; replacing HarvestBank hides unrelated upstream changes. Neither an event nor a virtual currently exposes refill. Add a read-only deadline and one notification after a real refill; keep logic additive in customizations. Apply with the normal patch gate.
- Pinned `HarvestTarget.OnTarget` dispatches `IChoppable` before normal lumber harvesting, so axe-targeting a marker can send the normal no-wood cliloc without changing the harvest target code.
- Pinned Item has `SkipSerialization`; GenericEntityPersistence excludes such entities from save indexes. Use it, plus defensive deletion on deserialization. No bank or stump state needs persistence.

## Built behavior

- `server/customizations/ClusterFLumberStumps.cs`: a Lumberjacking partial uses the existing `OnHarvestFinished` virtual. It checks the definition, validates the tree target, resolves its map and exact XYZ, and verifies the bank is that target's bank. A successful harvest that leaves less than one harvest of wood marks that tree. A failure with harvestable wood does not mark it. A dictionary keyed by the actual `HarvestBank` prevents duplicate markers. Mining never enters this path.
- One temporary, immovable `ChoppedTreeStump` appears at the targeted static's XYZ, preserving its base Z rather than using the player's Z. No tree static is removed or replaced. Other trees in the same bank remain visually unchanged. The single-click label (also the item name) is exactly `This tree has been chopped clean.`
- Both double-clicking the marker while holding an axe and targeting it with the axe report cliloc 500493, the normal `There's not enough wood here to harvest.` The marker implements `IChoppable`, which pinned `HarvestTarget` already dispatches. Range is two tiles, as stock lumber; an unequipped axe gets stock cliloc 500487.
- `server/patches/HarvestBank-lumber-stumps.patch` adds a read-only `NextRespawn` and calls the registry after a real refill. It is registered in `docker/uo/apply-patches.sh`. A per-marker timer deletes the item at the bank's original deadline even if nobody touches the bank again. Any earlier refill deletes it immediately and cancels its timer. Manual deletion also clears the registry.
- `SkipSerialization = true` excludes markers from normal world saves; a generated `[AfterDeserialization]` callback defensively deletes one if a forced/legacy load nevertheless contains it. Neither the marker nor the registry persists. Banks refill lazily as before; timer expiry only removes the visual.
- Settings are read at Configure with `GetOrUpdateSetting`: `clusterf.lumber.stumps` defaults to **true**. `clusterf.lumber.stumpItemId` defaults to **0**, meaning choose randomly per marker from **0x0E56–0x0E59**. An explicit nonzero ID chooses one fixed art, clamped to that range (decimal **3670–3673**). No new art is required.
- Player changelog and VERSION advanced together to `2026.10.21.21`.

### Marking every tree in the bank

Potentially worth a future opt-in setting, default **off**, if players find unmarked neighboring trees misleading: the whole 4 by 3 bank really is unavailable. It would require enumerating statics at every tile and distinguishing trunks from canopy/decorative components so one tree does not get several stumps. It also produces more world items, and they still sit underneath unchanged client trees. For this task only the final targeted tree is marked. No whole-bank setting was built. A client overlay is the cleaner future way to show all the bank's trees as exhausted without adding markers everywhere.
